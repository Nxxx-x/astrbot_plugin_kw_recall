# 消息撤回

群消息命中**关键词、号码、链接、二维码、Emoji** 后，由机器人调用 QQ 官方接口撤回。带一个 WebUI 管理页，五类可独立开关，并各配一条提示文案。

## 安装

```bash
cd AstrBot/data/plugins
git clone <仓库地址> astrbot_plugin_kw_recall
pip install opencv-python-headless regex
```

`opencv-python-headless` 给二维码识别用，`regex` 给 Emoji 判断用，两个都是可选的：不装时对应那一类会降级，其余照常。装完在 WebUI → `插件` 页重载插件，卡片详情页即可看到「消息撤回」视图。

WebUI 视图依赖 `register_web_api` 和 `views/`，需要较新的 AstrBot（4.2x 及以上）。老版本只能加载失败，别勉强。

## 三个前提（不满足就用不了）

| 前提 | 不满足的后果 |
|---|---|
| 机器人被群主设为**群管理员** | 撤别人消息返回 `40062003 无操作权限` |
| 群主开启「**接收全量消息**」 | 只看得到 @ 机器人的消息，命中率极低 |
| 消息在 **2 分钟内** | 返回 `40064004 已超出消息撤回时限` |

群主/管理员发的消息不会被撤回（代码里直接跳过，既避免冒犯也避免无权限报错）。

## 五类命中规则

| 类型 | 默认 | 命中条件 |
|---|---|---|
| 关键词 | 开启 | 子串包含，不区分英文大小写。`加群` 命中「快来加群领福利」 |
| 号码 | 关闭 | 5 位及以上**连续**数字 |
| 链接 | 关闭 | 协议头、`www.`、常见域名后缀、裸 IP |
| 二维码 | 关闭 | 图片里能解码出二维码 |
| Emoji | 关闭 | 消息里出现 😀 这类 Unicode 字符 |

号码：`12345`、`123456456789`、`价格 88888 元` 都算；`123 45`、`123-45`、`1234` 不算。全角数字同样算。

链接：`https://example.com/a`、`www.abc.com`、`abc.com`、`hello@qq.com`、`192.168.1.1` 都算；`main.py`、`3.14`、`1.2.3` 不算（后缀不在常见域名表里）。域名后缀表在 `main.py` 的 `LINK_RE` 里，可以自己加。

二维码：下载消息里的图片，用 OpenCV 解码。一条消息最多看 4 张图，单张超过 10MB 跳过，下载超时 8 秒。**只有开关打开时才会下载解码**，平时零开销。

## Emoji 怎么判断

只认 **Unicode emoji 字符**：😀 ❤️ 👍 🇨🇳 这类用户用键盘打出来的表情。

判断按 Unicode 属性走。装了 `regex` 时用字素簇（`\X`）+ `Extended_Pictographic`，`👨‍👩‍👧`、`👍🏽`、`🇨🇳`、`1️⃣` 都只算 1 个；没装则退回内置区段匹配，个别组合表情会多算，只影响日志里的个数。

出现一个就撤，没有数量阈值，也不要求整条消息都是表情。`哈哈😀` 和 `😀😀😀` 处理一致。代价是正常聊天带表情也会被撤，建议只在高发群开。

### QQ 自带表情不撤

QQ 原生表情、超级表情（小黄脸、收藏的表情包）不是字符，官机下发的是 `<faceType=4,...>`，适配器会转成 `[表情:捂脸]` 这样的标签。这类**不纳入撤回**——它是 QQ 的表情，不是用户打的 emoji。

匹配前会先把这些标签从文本里剥掉，所以标签里的描述文字也不会误伤：`[表情:笑哭]` 不会因为关键词里设了「笑哭」而被撤，`[表情:12345]` 也不会被当成号码。只有整条消息的文字部分（`[表情:笑哭]哈哈` 里的「哈哈」）参与判断。

图片形式的贴纸、GIF 表情包在官机里就是普通图片附件，文本为空，同样不会触发 Emoji 规则。

### @ 也不参与判断

官机的 @ 是 `<qqbot-at-user id="openid" />` 或 `<@!openid>` 标签，适配器只会提前剥掉 @ 机器人自己的那一个，@ 别人的标签会留在文本里。openid 里常带一长串数字和字母，于是：

- `@某人` 的 openid 被号码规则当成电话/QQ 号，整条消息被撤；
- openid 里的字母还可能误命中关键词。

现在 @ 标签和 `[表情:…]` 一起，在匹配前统一剥掉。`@小明 我的号 88888` 仍按真号码撤，但 `@小明 你好` 不会有任何动作。

## 五类提示文案

每一类都有自己的回复文案，在 WebUI 里对应右侧输入框；留空表示这一类撤回后不发言。

- `撤回后发送提示` 是总开关，关掉则五类都不发提示。
- `提示时 @ 被撤回的人` 开启后提示前会带 at，仅总开关打开时可用。
- 官机的 @ 会被适配器转成 `<qqbot-at-user id="openid" />` 内联进文本，不是 OneBot 的 CQ 码，所以用的是发送者的 openid。
- 提示本身也是一条消息，同样受被动回复窗口和频率影响。默认不发，省主动消息频次。

## 群指令（仅 AstrBot 管理员）

```text
/撤回词                查看总状态、五类开关与词表
/撤回词 +加群          添加关键词
/撤回词 -加群          删除关键词

/撤回关键词 开|关
/撤回号码 开|关
/撤回链接 开|关
/撤回二维码 开|关
/撤回表情 开|关

/撤回回复              查看五类当前文案
/撤回回复 链接 请勿发链接   设置某一类的文案
/撤回回复 号码 -         清空文案（该类撤回后不发言）
```

## 数据存放

关键词、五类开关与文案、计数存在插件 KV 里（`data/plugin_data/` 下），不写插件自身目录，更新插件不会丢。

旧版本（只有号码开关和单一提示文案）的数据会在首次读取时自动迁移：`recall_numbers` → 号码开关，`notify_text` → 关键词文案。新增的 Emoji 开关缺失时按默认关闭补齐。

## 已知限制

- 只做了群聊撤回，单聊撤回接口（`DELETE /v2/users/{openid}/messages/{message_id}`）没接。
- 关键词是纯字符串包含，不支持正则。
- 二维码只认图片消息里的码，不认「二维码链接」或小程序卡片。
- 只认 Unicode emoji；QQ 自带表情（`[表情:…]` 标签）和图片表情包都不撤，这是有意为之。
- 二维码解码是 CPU 操作，图片多、群消息快时会有百毫秒级延迟，已用线程池 + 锁避免阻塞事件循环。
- 未装 opencv 时二维码开关静默失效；未装 regex 时 Emoji 计数退回粗匹配，都会在日志里提示。
- 撤回失败会记在 `last_error` 里，在管理页底部显示最近一条。
