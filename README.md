# 消息撤回 · QQ 官方机器人

给 AstrBot 的 QQ 官方机器人（`qq_official` / `qq_official_webhook`）加一层「自动撤回」：群消息命中 **违禁词 / 链接 / 号码 / 二维码 / Emoji** 就调用官方接口撤回，并可选发一条带艾特的提示。

全自动判定，只有一条群内入口 `菜单`（弹出按钮面板）。五类规则**默认全部开启**，装完即生效，其余设置都在 AstrBot 管理面板里。

| | |
|---|---|
| 支持平台 | `qq_official`、`qq_official_webhook` |
| AstrBot 版本 | `>= 4.16,< 5` |
| 当前版本 | 1.13.0 |
| 依赖 | `opencv-python-headless`、`regex`（均可选，缺失只影响对应功能） |
| 许可 | MIT |

## 为什么需要它

QQ 官机的群消息撤回有几个绕不开的限制：接口没被 SDK 封装、只能撤 2 分钟内的消息、必须机器人是群管理员。这个插件把这些细节收在一处：命中规则就发 `DELETE /v2/groups/{group_openid}/messages/{message_id}`，失败按错误码分级记日志，不会因为一条漏撤刷满控制台。

常见的用法是拦广告——「加群」「代刷」这类违禁词、一条外链、一串手机号、一张拉群二维码、一段刷屏 emoji，都在群规之外自动清掉。

## 指令

只注册一条命令，没有指令组：

| 指令 | 说明 | 谁能用 |
|---|---|---|
| `菜单` | 弹出撤回开关面板：五类规则 + 撤回提示，一行两个按钮，点一下即切换 | 谁都能发；按钮仅群主/管理员可点 |

- **两种写法都行**：群里直接发 `菜单`，或按 AstrBot 的唤醒前缀发 `/菜单`。它注册成了真正的 AstrBot 命令（`filter.command`），受框架的唤醒前缀与指令解析管理。
- **精确匹配**：`菜单啊`、`菜单 你好` 都不触发；首尾空格自动忽略。
- **不受撤回规则影响**：这条在五类规则之前处理，即使「菜单」被写进违禁词表，也不会被自己撤掉。
- **没有子命令**：不存在 `/撤回`、`/开关` 之类，也不响应、不改写其他文本。
- **仅群聊**：只处理群消息，私聊发 `菜单` 不会响应。

面板长什么样、点完回什么，见下面的 [群内菜单](#群内菜单)。

## 五类规则

| 规则 | 判定方式 | 默认 | 典型命中 |
|---|---|---|---|
| 违禁词 | 子串包含，不区分大小写，最多 200 词 | 开 | `加群` 命中「快来加群领福利」 |
| 链接 | 协议头、`www.`、常见域名后缀、裸 IP | 开 | `https://x.com/a`、`abc.cn`、`192.168.1.1` |
| 号码 | 连续 5 位及以上数字 | 开 | `13800138000`、`价格 88888 元` |
| 二维码 | 下载图片用 OpenCV 解码，读出内容即撤 | 开 | 拉群码、收款码截图 |
| Emoji | 出现任意 Unicode emoji 就撤，无数量阈值 | 开 | 😀 ❤️ 👍 `1️⃣` |

匹配顺序为 **违禁词 → 链接 → 号码 → Emoji**；文本没命中时才去解码图片。一条消息只按第一个命中的规则处理，提示文案也取那一类的。

## 安装

**方式一：插件市场**（推荐）

AstrBot 管理面板 → 插件市场 → 搜索「消息撤回」→ 安装。

**方式二：手动放目录**

```bash
cd AstrBot/data/plugins
git clone https://github.com/Nxxx-x/astrbot_plugin_kw_recall.git
```

**方式三：上传 zip**

把 `astrbot_plugin_kw_recall.zip` 解压到 `AstrBot/data/plugins/`。

> 覆盖安装前先删掉旧的 `astrbot_plugin_kw_recall` 目录，避免旧版本残留文件（如老版本的 `views/`）一起被加载。

装完在「插件」页点重载。依赖会随插件自动安装；装不上也不影响除二维码外的四类功能。

## 配置

管理面板 → 插件 → 消息撤回 → 配置，保存即生效。

| 配置项 | 默认 | 说明 |
|---|---|---|
| 菜单标题 | `RECALL SETTINGS` | 群里发 `菜单` 时按钮上方那行字，最多 40 字；**只能在这里改**，菜单里没有改标题的按钮 |
| 撤回后发提示并艾特发送者 | 开 | 关掉则只撤回、不发言；开着时提示会艾特被撤回的人 |
| 违禁词 · 启用 | 开 | 子串包含，不区分大小写 |
| 违禁词 · 列表 | 空 | 多行文本，一行一个；词表为空时该规则不生效 |
| 号码 · 启用 | 开 | 连续 5 位及以上数字 |
| 链接 · 启用 | 开 | 协议头、`www.`、域名后缀、裸 IP |
| 二维码 · 启用 | 开 | 图片中能解码出二维码 |
| Emoji · 启用 | 开 | Unicode emoji，有一个就撤 |

每组还有一个「提示文案」，默认分别是：

- 违禁词：`消息含有违禁词，已撤回`
- 号码：`请勿发送号码，已撤回`
- 链接：`请勿发送链接，已撤回`
- 二维码：`请勿发送二维码，已撤回`
- Emoji：`请勿发送emoji，已撤回`

把某一类的文案**留空**，这一类就静默撤回、不发言——比如号码静默清掉，违禁词才提示。

没有总开关，不想管哪一类就单独关掉这一类。

## 群内菜单

在群里发 `菜单`，机器人回**一条**带按钮的消息，6 个开关一行两个、正好排成三行：

```text
RECALL SETTINGS
[ 撤违禁词 开 ]  [ 撤回链接 开 ]
[ 撤回号码 开 ]  [ 撤二维码 开 ]
[ 撤回表情 开 ]  [ 撤回提示 开 ]
```

正文就是**菜单标题**（默认 `RECALL SETTINGS`，在插件设置里可以改成任意一句话）；开关状态全写在按钮文案上，开是蓝底、关是灰底。文案都压到 4 个字，是为了半屏宽也放得下。

点一下按钮立即切换，并回一句最短的回执，把「撤回」挪到后面读起来像个结论：

| 点了什么 | 回执 |
|---|---|
| 关掉违禁词 | `违禁词撤回 关` |
| 打开链接 | `链接撤回 开` |
| 关掉二维码 | `二维码撤回 关` |
| 关掉撤回提示 | `撤回提示 关` |

只有配置写不进去时才回「保存失败，请到面板改」。想确认最新状态，直接看回执，或者再发一次 `菜单` 重新渲染按钮。

几个要点：

- **谁发「菜单」都能拿到面板**，但按钮只有群主/管理员点得动。AstrBot 自己下发键盘时把权限写死成 `permission.type = 2`（所有人可点），所以这里绕开它自己拼 keyboard，用 `type = 1`（仅管理者可操作），普通成员点下去客户端直接拦掉，点击事件根本不会推给机器人。
- **6 个开关一条消息放得下**：一行两个正好三行，QQ 键盘一条最多 5 行。
- **标题只能在插件设置里改**：菜单本身不提供「改标题」的按钮，也不接受聊天指令改标题；换行会被压成一行，超过 40 字截断，留空回退默认值。
- **提示开着就一定艾特**：「撤回提示」只有开与关，不再单列艾特开关；不想艾特只能把整个提示关掉。
- **点按钮改的是同一份配置**，会写回 `data/config/astrbot_plugin_kw_recall_config.json`，和面板里改完全等价，重启不丢。
- **回执只有一行**，形如 `违禁词撤回 关`。不给回执的话按钮还停在旧文案上，分不清是没点到还是没生效；再长的说明就没必要了。
- **按钮没有有效期**，随时可点。
- **正文不能真的空着**。官机没有「只有按钮」的消息类型，按钮必须挂在 text / markdown 正文上。正文发空串会被平台收下、keyboard 一起被丢掉，群里只剩一个空白气泡（v1.11.2 踩过）。所以正文总会有一句标题（默认 `RECALL SETTINGS`，留空也会回退成它），markdown 发不出去就退纯文本重发，按钮照挂；两档全被拒才降级成一行纯文本状态。

> 「菜单」这条消息在所有规则之前处理，即使你把「菜单」设成了违禁词，也不会被自己的规则撤掉。

## 判定细节

**号码**：正则 `\d{5,}`，数字必须彼此紧邻。

| 消息 | 结果 |
|---|---|
| `12345`、`123456456789`、`价格 88888 元` | 撤 |
| `123 45`、`123-45` | 不撤（被空格、符号断开） |
| `1234` | 不撤 |

**链接**：`https://example.com/a`、`www.abc.com`、`abc.com`、`hello@qq.com`、`192.168.1.1` 都算；`main.py`、`3.14`、`1.2.3` 不算。后缀表在 `main.py` 的 `LINK_RE`。

**二维码**：一条消息最多看 4 张图，单张超 10MB 跳过，下载超时 8 秒，解码超时 10 秒。同一张图只解码一次。

**Emoji**：只认 Unicode 字符，没有数量阈值。`👨‍👩‍👧`、`👍🏽`、`🇨🇳`、`1️⃣` 都算命中。

### QQ 自带表情和 @ 不参与判断

官机里 QQ 原生表情不是字符，适配器会转成 `[表情:捂脸]` 标签；@ 是 `<qqbot-at-user id="openid" />` 或 `<@!openid>`。两者都留在 `message_str` 里。

匹配前会统一剥掉，原因有两个：

- `[表情:捂脸]` 不该触发 Emoji 规则——那是 QQ 的表情，不是用户打的 emoji；
- 标签内容不该误伤：`[表情:笑哭]` 不会命中违禁词「笑哭」，`@某人` 的 openid 也不会被当成号码。

所以 `@小明 我的号 88888` 照撤，`@小明 你好` 不动。

## 使用前提

1. 机器人必须是**群管理员**，否则撤成员消息返回 `40062003`；
2. 消息发出后 **2 分钟内**才能撤，超时返回 `40064004`；
3. 群主要放开「**接收全量消息**」，否则机器人只看得到 @ 它的消息，其余消息根本收不到。

群主和管理员自己发的消息不会被撤回——既避免得罪人，也避免无权限报错。

## 常见问题

**发了违规消息但没撤？**

按顺序排查：机器人是不是群管理员 → 消息是否已超 2 分钟 → 群是否开了「接收全量消息」→ 发消息的人是不是群主/管理员 → 对应规则是否开着、违禁词是否在词表里。日志里搜 `[kw_recall]` 能看到命中原因或失败码。

**发「菜单」没反应？**

先确认机器人收到了这条消息（群要开「接收全量消息」）；能回出纯文本状态但没按钮，多半是机器人没有 markdown / 按钮权限。另外触发词必须就是「菜单」：`菜单啊`、`菜单 你好` 都不算，`/菜单` 可以。

**按钮点了没动静？**

普通成员点不动是预期行为（按钮权限是「仅管理者可操作」），面板本身任何成员发 `菜单` 都能调出来。

管理员点了也只是回一句「xxx撤回 关」这种回执，不会弹出新面板。连回执都没有，就照这三行日志定位（`data/logs` 里搜 `[kw_recall]`）：

| 日志 | 含义 |
|---|---|
| `v1.12.0 已加载，按钮入口：button_action` | 新版本已生效，点击能派到插件 |
| `按钮点击 → 撤回链接` | 事件收到了，接着应该跟一行 `面板切换 撤回链接 → 关` |
| 只有「已加载」、没有「按钮点击」 | 事件没派进来：确认面板是升级后重新发的（发一次 `菜单` 应回一条、六个按钮），再不行就是 AstrBot 版本太旧 |

回执被平台挡住时开关其实已经改了，重新发一次 `菜单` 看按钮文案就能确认。

**撤回了但没看到提示？**

确认「撤回后发送提示」是开的，并且这一类的提示文案不为空。

**提示里 @ 不出来，只是一段纯文本？**

官方文档对群消息 @ 的支持并不明确，部分账号/版本渲染不出蓝字 @。v1.12.0 起提示与艾特合并，已经不能单独关艾特：渲染不出来时只能把「撤回提示」整个关掉，撤回本身不受影响。

**二维码规则没反应？**

先看启动日志有没有 `未安装 opencv-python-headless`。装不上就关掉这一类，其余四类不受影响。二维码默认开启，如果群里图片量大、又不需要查码，建议关掉——每条带图消息都会先下载再解码。

**改了配置没生效？**

配置是保存到 `data/config/astrbot_plugin_kw_recall_config.json` 的。旧版本升级上来的配置文件会保留已有值，包括旧文案；想回到默认值，把那一项清空后保存，或在面板里删掉对应条目。

**会不会影响 AI 回复？**

不会。插件只是旁听群消息，命中才撤回，不阻断后续处理；全程只有 `菜单` 一个入口词，不带 `/` 前缀，不会和别的插件的命令抢前缀。

**会不会撤回机器人自己的消息？**

不会。官机不把机器人自己发的消息推给机器人，撤回提示也不参与自己的规则判断。

**支持私聊或其他平台吗？**

只处理官机群消息。私聊、aiocqhttp、Telegram 等平台完全不介入。

## 实现与性能

群消息是高频路径，每条都要过一遍规则，所以做了几处收敛：

- **词表缓存**：违禁词列表只在配置文本变化时重新解析，并预存小写形式，每条消息只 lower 一次正文；
- **Emoji 短路**：规则只关心「有没有」，命中第一个就返回，不做全量计数；
- **二维码缓存**：同一张图（按落盘文件名 / URL）只解码一次，最多记 256 条，超出按最久未用淘汰；
- **解码限流**：解码放线程池，最多 2 并发，单张限时 10 秒，不拖住事件循环；
- **日志分级**：超时 `40064004`、无权限 `40062003` 只写 debug，其他异常才 warning。

撤回用的是 botpy 的 `Route` + `DELETE`，botpy 新旧版本 `api._http` / `api.http` 两种挂载都做了兜底。
